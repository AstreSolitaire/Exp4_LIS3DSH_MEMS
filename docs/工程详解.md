# 工程详解（简化版）

本工程按"**功能保留、实现最简**"组织：实验要求的全部功能都在，但用户代码只有
`Core/Src/main.c` 一个文件、10 个函数。其余 `spi.c / usart.c / rtc.c / gpio.c /
stm32f4xx_it.c / hal_msp.c / system_stm32f4xx.c` 都是 CubeMX 生成的标准文件，不需要改。

---

## 一、main.c 的结构

```
        ┌─ fputc()                  printf 重定向：阻塞发 1 字节
        ├─ LIS3DSH_Write()          写一个寄存器（2 字节 SPI 帧）
        ├─ LIS3DSH_Read()           读 N 个寄存器（逐字节）
        ├─ LIS3DSH_Init()           读 ID 自检 + 写 3 个控制寄存器
        ├─ LIS3DSH_GetXYZ()         读 6 字节输出并换算成 mg
        ├─ Uart_Cmd()               解析 $0,1,...* / $0,5,x*
        ├─ HAL_GPIO_EXTI_Callback() INT1 中断：只置标志、计数
        ├─ HAL_UART_RxCpltCallback()串口中断：组帧，收满置标志
        ├─ HAL_UART_ErrorCallback() 串口出错：重挂接收
        └─ main()                   初始化 + 主循环
```

`SystemClock_Config()`、`Error_Handler()` 是 CubeMX 生成的，不用动。

---

## 二、SPI 访问（4 线，CS=PE3）

LIS3DSH 的地址是 **7 位**，命令字节最高位只表示方向：

```
bit7 = 1 -> 读；bit7 = 0 -> 写；bit6..0 = 寄存器地址
```

写一个寄存器：

```
CS↓  [addr]  [data]  CS↑
```

读一个寄存器（发哑字节换回数据）：

```
CS↓  [addr|0x80]  [0x00]  CS↑      -> 收到的第 2 字节就是数据
```

代码就 6~8 行，没有 DMA、没有中断，SPI 时钟 5.25 MHz（84 MHz / 16）。

> **易错点**：不要照搬网上 LIS3DH 的 `addr | 0x80 | 0x40` 写法。LIS3DSH 的地址排到
> 0x7F，bit6 也是地址的一部分；它的连续读自增由 CTRL_REG6 的 ADD_INC 控制。
> 本工程逐字节读，完全绕开这个问题，也与 ST 官方 `LIS3DSH_ReadACC()` 一致。

## 三、寄存器配置

| 寄存器 | 写入 | 含义 |
|---|---|---|
| `CTRL_REG5` 0x24 | `0x00` | ±2 g，抗混叠 800 Hz，4 线 SPI |
| `CTRL_REG4` 0x20 | `0x67` | ODR = 100 Hz（0110），X/Y/Z 使能 |
| `CTRL_REG3` 0x23 | `0xF8` | DRDY 送 INT1，高有效脉冲，INT1/INT2 引脚使能 |

换算：±2 g 时 0.06 mg/LSB，即 `mg = raw * 6 / 100`（整数运算）。

## 四、采样与上传

```
LIS3DSH 100Hz ──DRDY──> INT1(PE0) ──> EXTI0 中断 ──> s_drdy = 1, s_drdyCnt++
                                                        │
主循环：if (s_drdy 或 20 ms 超时) ──> 读三轴 ──> 事件判断
        if (每 200 ms) ──> printf 一行（时间 + X/Y/Z）
```

- **中断里只做两件事**：置标志、计数。SPI 读取、printf 都在主循环，避免中断里长时间阻塞。
- **20 ms 兜底**：INT1 没接或脉冲丢失时，主循环自己按 20 ms 读一次，数据流不中断。
- **上传 5 Hz**：9600 波特率下一行约 40 字符，40 ms 发完，200 ms 周期绰绰有余。

## 五、事件与命令

| 功能 | 判据 / 帧格式 | 代码位置 |
|---|---|---|
| 自由落体 | `x²+y²+z² < 300²`（用平方比较，省去开方） | 主循环采样后 |
| 超阈值 | 任一轴 `> 1500 mg` 或 `< -1500 mg` | 主循环采样后 |
| 改时间 | `$0,1,YYMMDD,HHMMSS*` | `Uart_Cmd()` |
| 开关上传 | `$0,5,1*` / `$0,5,0*` | `Uart_Cmd()` |

命令收帧用状态机：收到 `$` 开始，收到 `*` 结束并置 `s_cmdRdy`，主循环再解析，
这样中断里不做 `sscanf`、不 printf。

> **易错点**：阈值常量要写成**有符号**数（`1500` 而不是 `1500U`），否则 `int16_t`
> 与无符号常量比较时整型提升，`< -1500U` 会恒成立，静止时误报 HIGH-G。

## 六、简化前后对比

| 项目 | 原来（完整版） | 现在（简化版） |
|---|---|---|
| 用户源文件 | `main.c` + `lis3dsh.c/h` + 自带 DMA 的 `usart.c` | **只有 `main.c`** |
| 子函数 | 约 24 个 | **10 个** |
| 串口发送 | DMA + 512 B 环形 FIFO | `HAL_UART_Transmit` 阻塞 |
| RTC | 1 Hz 唤醒中断 + 全局字符串 | 打印前直接 `HAL_RTC_GetTime` |
| 事件 | 独立函数 + 平方根 | 主循环里两段 if |
| 代码大小 | 17 158 B | **12 666 B** |

功能没有减少：自检、100 Hz 采样、INT1 中断、5 Hz 上传、时间戳、自由落体/超阈值、
串口改时间与开关上传都保留。

## 七、上板现象

- 上电：`[OK] LIS3DSH ready: 100 Hz, +-2 g`，LD3 亮；
- 静止：`Z ≈ +980 mg`，每 200 ms 一行；
- 翻转：对应轴 ±1000 mg 左右；
- 自由落体/晃动：`[EVT] FREE-FALL` / `[EVT] HIGH-G`，LD5 闪 300 ms；
- 每 10 s：`[STAT] drdy=... rx=... err=...`，`drdy` 每秒约 +100；
- LD6 常亮表示 INT1 中断正常。

配套的图形监测软件见 `tools/serial_monitor.py`（桌面有快捷方式）。
